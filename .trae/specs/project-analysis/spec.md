# BIGZ Hub 项目分析与改进方案

## Why

当前 BIGZ Hub MVP 版本已完成核心功能，但在功能性、用户体验、安全性、可扩展性和代码质量等方面存在改进空间。本文档旨在系统性地分析现有缺陷、识别可拓展方向，并提出应增添的功能方案。

***

## Impact

* **Affected specs**: 用户系统、通知系统、作业系统、论坛系统、聊天系统、搜索系统

* **Affected code**: app.js、views/、public/js/、数据库结构

***

## 一、当前项目缺陷分析

### 1.1 技术架构缺陷

| 缺陷类别   | 具体问题                                            | 严重程度 |
| ------ | ----------------------------------------------- | ---- |
| 前端架构   | 使用原生 EJS 模板渲染，组件化程度低，无现代前端框架                    | 高    |
| 实时性能   | 聊天采用页面刷新/轮询方式，未利用已引入的 `ws` 库实现 WebSocket        | 高    |
| API 设计 | RESTful API 不完整，部分操作只能通过表单提交（如创建考试、作业）          | 中    |
| 安全性    | 缺少 CSRF 保护、密码重置功能缺失、rate limit 仅存储在内存中          | 高    |
| 数据库    | SQLite 并发写入性能有限，缺少数据库迁移版本控制（migrate.js 仅为一次性脚本） | 中    |
| 代码组织   | 全部逻辑集中在 app.js（2600+ 行），模块化程度低                  | 高    |

### 1.2 功能缺陷

| 功能模块 | 缺陷描述                                           | 影响 |
| ---- | ---------------------------------------------- | -- |
| 通知系统 | 数据库有 `notifications` 表，但无独立的通知查看页面，通知无法被用户真正查阅 | 高  |
| 聊天系统 | 仅支持全站广播式聊天，无私信功能、无群组功能、无@提及                    | 高  |
| 论坛系统 | 无嵌套评论、无帖子收藏/点赞、无标签系统、搜索结果简陋                    | 中  |
| 作业系统 | 仅支持查看和标记完成，缺少教师布置作业、提交作业、作业批改功能                | 高  |
| 搜索功能 | 搜索结果单一，无高级筛选、无搜索历史、无热门搜索推荐                     | 中  |
| 用户主页 | 无用户个人主页、无贡献历史展示、无积分/等级成就展示                     | 中  |

### 1.3 用户体验缺陷

| 问题     | 描述                              |
| ------ | ------------------------------- |
| 移动端体验  | 响应式布局但交互层、按钮大小等未针对移动端优化         |
| 错误处理   | 表单验证错误展示不够友好，部分错误仅跳回上一页无明确提示    |
| 加载状态   | 无骨架屏（shimmer 动画过于简陋）、无优雅的加载状态展示 |
| 深色模式   | 完全缺失夜间模式                        |
| 无空状态引导 | 各列表为空时仅显示简单文字，无引导用户创建内容的入口      |

## 二、可拓展方向

### 2.1 技术升级方向

| 方向            | 描述                                     | 优先级 |
| ------------- | -------------------------------------- | --- |
| 前端 SPA 化      | 引入 Vue 3 或 React，构建单页应用，提升交互体验         | 高   |
| WebSocket 实时化 | 利用已引入的 `ws` 库实现实时聊天、实时通知推送             | 高   |
| API First     | 完善 RESTful API，所有功能均可通过 API 调用，支持前后端分离 | 中   |
| TypeScript 迁移 | 将 app.js 拆分为多个模块，引入 TypeScript 类型检查    | 中   |
| 数据库迁移系统       | 引入正式的数据库迁移工具（如 node-pg-migrate）        | 中   |

### 2.2 功能扩展方向

| 方向     | 描述                    | 优先级 |
| ------ | --------------------- | --- |
| 私信系统   | 学生间一对一私信、群聊功能         | 高   |
| 通知中心   | 独立的通知页面，支持已读/未读、分类型查看 | 高   |
| 作业系统增强 | 教师布置作业、学生在线提交、作业批改反馈  | 高   |
| 收藏功能   | 收藏帖子、资源、作业等，支持个人收藏夹   | 中   |
| 课程表    | 可视化课程表，支持周视图          | 中   |
| 成绩查看   | 各学科成绩录入与查看            | 中   |
| 活动日历   | 校园活动、考试倒计时等时间线功能      | 低   |

***

## 三、应增添的功能清单

### 3.1 高优先级功能

#### F1: 通知中心系统

**现状**: 有 `notifications` 表但无通知页面

**方案**:

* 创建 `/notifications` 页面，展示所有通知

* 支持按类型筛选（审核结果、系统通知、互动通知）

* 支持一键全部标为已读

* 支持 WebSocket 实时推送新通知

* 头部导航增加通知图标及未读数量角标

**影响**:

* 新增 `notifications` 视图页面

* 修改 `app.js` 新增通知相关路由

* 通知实时推送需要 WebSocket 集成

***

#### F2: 私信系统

**现状**: 只有全站广播式聊天

**方案**:

* 创建 `conversations` 表存储会话

* 创建 `messages` 表存储私信消息（复用现有 `chat_messages` 表结构）

* 支持一对一私信

* 支持@提及自动发送通知

* 消息支持文本、Markdown渲染

**影响**:

* 新增数据库表：`conversations`, `conversation_participants`

* 新增视图页面：`/messages`, `/messages/:conversationId`

* 新增 API 端点

***

#### F3: 作业提交与批改系统

**现状**: 学生只能标记作业完成状态，无教师布置/批改功能

**方案**:

* 教师可创建作业并设置截止时间、满分分值

* 学生可在线提交作业（支持文本输入和文件上传）

* 教师可批改作业并给出分数/评语

* 学生可查看作业批改结果

* 作业状态流转：待提交 → 已提交 → 已批改

**影响**:

* 新增数据库表：`assignments`, `assignment_submissions`

* 新增视图页面：`/assignments`, `/assignments/:id`, `/assignments/:id/submit`

* 新增 API 端点

* 需要区分用户角色（学生/教师）

***

### 3.2 中优先级功能

#### F4: 收藏功能

**方案**:

* 支持收藏帖子、资源、作业等

* 创建 `/favorites` 个人收藏页面

* 收藏时可选是否添加备注

**新增表**: `favorites` (user\_id, item\_type, item\_id, note, created\_at)

***

#### F5: 课程表功能

**方案**:

* 管理员/教师可配置每学期的课程表

* 学生可查看自己年级的课程表

* 支持周视图展示

* 课程表可关联学科板块

**新增表**: `schedules`, `schedule_items`

***

#### F6: 深色模式

**方案**:

* 在 CSS 中定义暗色主题变量

* 支持系统级自动切换（prefers-color-scheme）

* 支持手动切换开关，状态持久化到 localStorage

***

#### F7: 帖子收藏与点赞

**方案**:

* 支持对帖子点赞（类似资源点赞）

* 支持收藏帖子到个人收藏夹

* 帖子列表按点赞数排序的"热门"选项已存在，需激活

**影响**: 复用现有 `resources` 表的 like\_count 逻辑到 `posts` 表

***

#### F8: 搜索增强

**方案**:

* 搜索结果页面支持分类筛选（帖子/资源/作业/考试）

* 支持搜索历史记录（localStorage）

* 热门搜索推荐

* 支持搜索结果分页

***

### 3.3 低优先级功能（可选拓展）

| 功能     | 描述                      |
| ------ | ----------------------- |
| 用户个人主页 | 展示用户发布的帖子、回答、资源贡献、积分成就等 |
| 活动日历   | 校园活动时间线，可视化重要日期         |
| 成绩查看   | 各学科成绩录入与历史查看（需权限控制）     |
| 举报系统   | 用户可举报违规内容，管理员可处理        |
| 积分商城   | 用积分兑换虚拟奖励/称号            |
| 成就徽章   | 完成特定行为解锁成就              |

***

## 四、代码层面改进建议

### 4.1 模块化重构

**问题**: app.js 过于庞大（2600+ 行）

**建议**:

```
server/
├── routes/          # 路由分离
│   ├── auth.js
│   ├── forum.js
│   ├── exams.js
│   ├── homeworks.js
│   └── ...
├── models/         # 数据模型分离
├── services/       # 业务逻辑分离
│   ├── notification.js
│   ├── credit.js
│   └── ...
├── middleware/      # 中间件分离
└── utils/          # 工具函数
```

### 4.2 前端组件化

**建议**: 将 views 中的重复 UI 抽取为组件

* 使用 Vue 3 构建组件库

* 复用组件：Card、Button、Form、Modal 等

### 4.3 安全性加固

| 改进项        | 当前状态         | 建议                   |
| ---------- | ------------ | -------------------- |
| CSRF 保护    | 无            | 引入 csurf 中间件         |
| 密码重置       | 缺失           | 引入邮件发送功能（nodemailer） |
| Rate Limit | 内存存储         | 改为 Redis 存储          |
| 输入验证       | 基础验证         | 引入 Joi/Zod schema 验证 |
| SQL 注入     | 使用参数化查询      | 良好，保持                |
| XSS        | 使用 DOMPurify | 良好，保持                |
