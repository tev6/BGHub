# 权限系统完整实现（基于新版文档）

## Why

需要根据最新的 `BG Hub社区信用等级与用户权限说明.md` 文档重构项目权限系统。新文档定义了更精确的等级权限、审核流程和举报/申诉机制。

## What Changes

### 1. 等级体系（LV0-LV6 + LV5.5）

| 等级 | 信用分 | 聊天发布 | 作业发布 | 文章发布 | 资源发布 | 举报上限 | 申诉上限 |
|------|--------|----------|----------|----------|----------|----------|----------|
| LV0 | 0 | AI审核(先审后发) | ❌ | ❌ | ❌ | ❌ | ❌ |
| LV1 | 1-10 | AI审核 | AI+人工复审 | ❌ | ❌ | 5次/日 | ❌ |
| LV2 | 11-40 | 直接发布 | AI+人工复审 | AI+人工复审 | ❌ | 5次/日 | ❌ |
| LV3 | 41-100 | 直接发布 | AI审核 | AI+人工复审 | ❌ | 10次/日 | 3次/日 |
| LV4 | 101-250 | 直接发布 | AI审核 | AI审核 | 人工审核 | 10次/日 | 5次/日 |
| LV5 | 251-500 | 直接发布 | AI审核 | AI审核 | 直接发布 | 20次/日 | 无限制 |
| LV5.5 | 特殊 | 直接发布 | 直接发布 | 直接发布 | 直接发布 | 20次/日 | 无限制 |
| LV6 | 最高 | 直接发布 | 直接发布 | 直接发布 | 直接发布 | 无限制 | ❌ |

### 2. 审核流程类型

| 流程 | 含义 | 适用 |
|------|------|------|
| AI初审+人工复审 | AI先判，通过后进入人工队列，人工确认后方可发布 | LV1-2作业、LV1-3文章 |
| AI审核 | AI判定通过即发布，无需人工干预 | LV0聊天、LV1-2聊天、LV3作业、LV4-5作业/文章 |
| 直接发布（免审） | 无需任何审核，直接上线 | LV2+聊天、LV4+资源、LV5+全部、LV3+部分 |
| 纯人工审核 | 不经过AI，直接由工作人员审核 | LV4+资源 |

### 3. 举报处理流程

根据被举报者等级决定审核方式：
- LV1-2：人工审核（由LV3+处理）
- LV3：人工审核（由LV4+处理）
- LV4：人工审核（由LV5+处理）
- LV5：需≥3人举报后进入人工审核（由LV5.5/LV6处理）
- LV5.5：需≥5人举报后进入人工审核（由LV6处理）

### 4. 申诉机制

- LV3+可申诉（LV1-2不可申诉）
- 申诉成功：撤销判定+补回信用分+额外补偿3分
- 申诉失败：维持判定+额外扣除3分+消耗额度

### 5. 恶意举报惩罚

| 次数 | 惩罚 |
|------|------|
| 首次判定 | 扣除5信用分，警告 |
| 累计3次 | 扣除15信用分，临时封禁1小时 |
| 累计5次 | 扣除30信用分，临时封禁24小时 |

### 6. 信用分规则

| 行为 | 变动 |
|------|------|
| 聊天消息通过AI审核 | +1 |
| 聊天消息审核失败 | -3 |
| 作业事项通过审核 | +3 |
| 作业事项审核失败 | -5 |
| 文章/笔记通过审核 | +5 |
| 文章/笔记审核失败 | -10 |
| 资源文件通过人工审核 | +5 |
| 资源文件审核失败 | -10 |
| 每日登录 | +1(LV1-2)/+2(LV3-4)/+3(LV5+) |
| 举报成功(聊天) | +1 |
| 举报成功(作业) | +3 |
| 举报成功(文章/资源) | +5 |

### 7. LV1触底机制

LV1信用分无法再降低时进入封禁机制：可游览但无法发布任何内容。封禁时长递进：5分钟→15分钟→45分钟→3小时→最高12小时。

### 8. IP封禁机制（仅LV0）

- 24小时内违规累计达30次，触发IP封禁6小时
- 封禁期间只能浏览+登录注册，登录后自动解除

## ADDED Requirements

### Requirement: 发布权限控制

系统必须根据用户等级控制发布权限。

#### Scenario: LV0用户发布聊天
- **WHEN** LV0用户发送聊天消息
- **THEN** 消息进入AI审核队列，审核通过后发布

#### Scenario: LV2用户发布聊天
- **WHEN** LV2用户发送聊天消息
- **THEN** 消息直接发布，无需审核

#### Scenario: LV1用户发布作业
- **WHEN** LV1用户提交作业
- **THEN** 作业先经AI审核，通过后再经人工确认方可发布

#### Scenario: LV0用户尝试发布作业
- **WHEN** LV0用户尝试发布作业
- **THEN** 系统拒绝并返回403错误

### Requirement: 举报系统

用户可举报违规内容。

#### Scenario: LV1用户举报
- **WHEN** LV1用户提交举报
- **THEN** 检查是否超过每日5次上限，未超则创建举报记录

#### Scenario: 举报处理-LV3用户被举报
- **WHEN** LV3用户被举报
- **THEN** 举报进入LV4+人工审核队列

#### Scenario: 举报处理-LV5用户被举报
- **WHEN** LV5用户被举报
- **THEN** 需≥3人举报才进入LV5.5/LV6人工审核

#### Scenario: 恶意举报惩罚
- **WHEN** 举报者连续3次举报均不成立
- **THEN** 扣除5信用分并警告

### Requirement: 申诉系统

LV3+用户可对误判内容申诉。

#### Scenario: LV3用户申诉成功
- **WHEN** LV3用户申诉内容被确认误判
- **THEN** 恢复内容、补回信用分、额外补偿3分、不消耗申诉额度

#### Scenario: LV4用户申诉失败
- **WHEN** LV4用户申诉被维持原判
- **THEN** 维持判定、额外扣除3分、消耗1次申诉额度

#### Scenario: LV2用户尝试申诉
- **WHEN** LV2用户点击申诉按钮
- **THEN** 系统拒绝，LV2不可申诉

### Requirement: LV1触底封禁机制

LV1用户信用分无法再降低时触发封禁。

#### Scenario: LV1触底封禁
- **WHEN** LV1用户信用分已为1，再次因违规需扣除信用分
- **THEN** 用户进入封禁状态（可浏览但不可发布），封禁时长5分钟起步

### Requirement: IP封禁

LV0用户频繁违规触发IP封禁。

#### Scenario: IP封禁触发
- **WHEN** IP在24小时内违规累计达30次
- **THEN** 封禁该IP 6小时，封禁期间只能浏览+登录注册

## MODIFIED Requirements

### Requirement: 聊天消息审核流程
**Modification**: LV0需先审后发(AI)，LV1需AI审核，LV2+直接发布

### Requirement: 申诉权限
**Modification**: 仅LV3+可申诉，LV1-2不可申诉

### Requirement: 每日申诉上限
**Modification**: LV3:3次/日, LV4:5次/日, LV5+:无限制

## Database Schema Changes

无需新增表，现有表结构已满足需求。需确保以下字段存在：
- daily_stats: reports_count, appeals_count
- reports: 支持举报类型和状态
- review_appeals: 支持申诉流程

## API Endpoints

### 举报相关 (LV1+)
- `POST /api/reports` - 提交举报（检查每日上限）
- `GET /api/reports/my` - 我的举报记录

### 申诉相关 (LV3+)
- `POST /api/appeals` - 提交申诉（检查每日上限）
- `GET /api/appeals/my` - 我的申诉记录

### 审核队列 (LV3+)
- `GET /api/review/queue` - 获取审核队列（按权限过滤）
- `POST /api/review/:id/approve` - 审核通过
- `POST /api/review/:id/reject` - 审核拒绝
- `POST /api/review/:id/appeal-decide` - 申诉裁决

### 管理相关 (LV6)
- `POST /api/admin/ban-ip` - 封禁IP
- `POST /api/admin/unban-ip` - 解禁IP
- `POST /api/admin/grant-lv55` - 授予LV5.5
- `POST /api/admin/revoke-lv55` - 撤销LV5.5
