## 二、灰度发布方案

### 2.1 灰度策略
```
阶段1（10%流量，1天）：
  - 仅启用新注册用户
  - 旧用户继续使用 v1.0.1

阶段2（50%流量，2天）：
  - 所有用户开启新功能
  - 监控系统稳定性

阶段3（100%流量）：
  - 全面启用 v2.0.0
  - 观察48小时
```

### 2.2 灰度监控指标
- API 响应时间 P99 < 500ms
- 错误率 < 0.1%
- 数据库查询性能
- 会话处理能力

## 三、回滚方案

### 3.1 自动回滚触发条件
- API 错误率 > 1%
- 响应时间 P99 > 2000ms
- 数据库连接失败
- 关键功能（登录/发帖）不可用

### 3.2 回滚步骤
```bash
# 1. 立即停止新版本部署
kubectl rollout undo deployment/bigz-hub

# 2. 恢复数据库（如有变更）
./db/rollback_v2.sh

# 3. 验证旧版本正常运行
curl http://localhost:3000/api/health

# 4. 通知相关人员
./scripts/notify.sh "BIGZ Hub 已回滚至 v1.0.1"
```

### 3.3 数据回滚注意事项
- credit_log 表保留不回滚（审计需求）
- admin_log 表保留不回滚（审计需求）
- review_items 状态保持不变
